Files vendored verbatim (NO trimming — Wayland opcodes are positional;
removing requests in the middle shifts numbering and breaks the wire
contract with the compositor).

One vendor patch applied: in `tizen-extension.xml`, the `tizen_policy.level`
enum's `none` entry has `value="-1"` upstream. Rust's `wayland-scanner`
rejects negative values in enum entries (they're parsed as u32). Patched
to `value="4294967295"` (= -1 reinterpreted as u32), which produces an
identical wire byte sequence. Look for "VENDOR PATCH" in the XML to find
it. To re-vendor: copy the upstream file, then reapply this single edit.

  tizen-extension.xml
      Source: protocol/tizen/tizen-extension.xml
      The full Tizen extension surface. Contains every Tizen-specific
      Wayland interface: tizen_policy (used by tizen-window for window
      visibility), tizen_input_device_manager, tizen_screenshooter,
      tizen_gesture, tizen_keyrouter, tizen_indicator, tizen_visibility,
      tizen_position, tizen_subsurface_watcher, tizen_renderer,
      tizen_move_resize, tizen_clipboard, tizen_display_policy, …
      Most of these aren't used by tizen-window directly, but vendoring
      the full file avoids opcode-shift bugs and means a Tizen protocol
      version bump is "drop in the new XML and rebuild".

  wtz-shell.xml
      Source: protocol/tizen/wtz-shell.xml
      The wtz_shell + wtz_surface interfaces — Tizen's per-surface

  wtz-screen.xml

      wtz_screen + wtz_splitscreen + wtz_splitscreen_region — referenced
